Repeatedly naming two unrelated items in the same breath (e.g. "T2-EM first firing · T1-FK opportunity" chanted across several reports) manufactures the impression of a mechanistic connection when the only shared property is bookkeeping ("both await a first field opportunity").

**Why:** User caught this 2026-07-08 — T2-EM (scope-mismatch exemption, run 20) and T1-FK (duplicate-manufacture detection, run 23) have nothing to do with each other; I was carrying them as an adjacent pair purely because both sat on the same watch checklist. Sibling of [[feedback-no-invented-labels]] (labels force results into stories) and the runs-are-variant discipline: co-mention is not evidence of relation.

**How to apply:** When reporting watch/status lists, name the CATEGORY once ("mechanisms still awaiting a first live opportunity") and enumerate members only when one actually fires or the user asks. Never let two ticket IDs travel together across multiple reports unless a mechanistic link is explicitly established and stated.
