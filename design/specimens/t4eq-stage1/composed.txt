Main (command-style):
- Running with no arguments exits with status 3 and prints an "unknown command" message to stderr [k44]
- Running with an unrecognized first argument exits with status 3 and prints "unknown command: " followed by that argument to stderr [k45]
- The "check" subcommand with no file argument exits with status 5 [k19, k46]
- The "check" subcommand with two file arguments exits with status 5 [k20, k47]
- The "count" subcommand with no file argument exits with status 5 [k48]
- The "count" subcommand with two file arguments exits with status 5 [k49]
- The "column" subcommand with only a file argument (missing the column name) exits with status 5 [k36, k50]
- The "column" subcommand with a file and two extra arguments exits with status 5 [k37, k51]
- A check on a file that does not exist is refused with a "no such file" message and exits 1 [k16, k52]
- A count on a file that does not exist prints an error message to standard error and exits with status 1 [k24, k53]
- A column on a file that does not exist prints "no such file: <path>" to stderr and exits 1 [k34, k54]
- A quoted field containing a comma is kept as a single field, so the row is not split at that comma [k1]
- A quoted field containing a double-quote is unescaped to a single double-quote in the field value [k2]
- A quoted field containing a newline is kept as one field, so the row is not split at that newline [k3, k4, k5]
- A row whose field count differs from the header is reported with the physical line where that row begins [k6, k7, k8, k9, k10]
- A CSV file whose header and every data row have the same number of fields is accepted as well-formed and the check exits 0 with no output [k11]
- A data row with fewer fields than the header is reported as malformed, naming the physical line where that row begins, and the check exits 2 [k12]
- A data row with more fields than the header is reported as malformed, naming the physical line where that row begins, and the check exits 2 [k13]
- When several data rows are malformed, each is reported on its own line with its physical line number, and the check still exits 2 [k14]
- The reported line number is the physical line where the row begins, so a row that starts on line 3 is reported as line 3 even though it is the second data row [k15]
- A check on an empty file (no rows at all) is treated as malformed input and exits 2 with no output [k17]
- A file containing only a header row (no data rows) is well-formed and the check exits 0 with no output [k18]
- A data row whose field count matches the header is not reported even if it appears after a malformed row, and the check still exits 2 because of the earlier mismatch [k21]
- When the count subcommand is given a CSV file with a header row plus N data rows, it prints N on standard output and exits with status 0 [k22, k25, k27, k28]
- When the count subcommand is given a CSV file containing only a header row (no data rows), it prints 0 and exits with status 0 [k23]
- When the column subcommand is given a file whose header contains the requested name, it prints the value of that column for each data row, one per line, and exits 0 [k32, k40, k41]
- When the requested column name is not present in the header, it prints "no such column: <name>" to stderr and exits 4 [k33, k42]
- When the file is empty (no rows), it prints "no such column: <name>" to stderr and exits 4 [k35]
- When a data row has fewer fields than the requested column index, that row contributes no output line while other rows still print their value [k38]
- When the file contains only a header row and no data rows, it prints nothing to stdout and exits 0 [k39]
