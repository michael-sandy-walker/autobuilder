StructuralDiffNode.isUnchanged:
In short: StructuralDiffNode.isUnchanged reports whether a node has changed. It returns false when one element is null and the other is present, or when both are present with different content. It returns true when both elements are present with equal content, including identical children and whole trees.

In short: DiffSummarizer.summarizePlainText renders a diff tree as plain text. It returns "(no changes)" when the root is unchanged and has no changed children. It formats added, deleted, and modified nodes with their type and id, indenting each child level by two additional spaces relative to its parent.

StructuralDiffUtils.flatten:
In short: StructuralDiffUtils.flatten converts a diff tree into a list of nodes. It returns a list whose first element is the root node, followed by its children in pre-order depth-first order. It returns a single-element list containing that node when the node has no children.
- StructuralDiffUtils.flatten(<root>) returns a list whose first element is the root node itself, followed by its children in pre-order (depth-first) order [k49]
- StructuralDiffUtils.flatten(<root>) returns a single-element list containing that node when the node has no children [k50]

StructuralDiffUtils.filterByType:
In short: StructuralDiffUtils.filterByType extracts nodes of a specific type from a diff tree. It returns only the nodes whose element type equals the requested type, in the same order flatten produces them. It returns an empty list when no node in the tree has the requested type.
- StructuralDiffUtils.filterByType(<root>, <type>) returns only the nodes (at any depth) whose element type equals <type>, in the same order flatten produces them [k51]
- StructuralDiffUtils.filterByType(<root>, <type>) returns an empty list when no node in the tree has the requested type [k52]
- StructuralDiffUtils.filterByType(<root>, <type>) identifies a method present only in the new content as an added METHOD node whose id contains the method name [k29]
- StructuralDiffUtils.filterByType(<root>, <type>) identifies a method present only in the old content as a deleted METHOD node whose id contains the method name [k30]
- StructuralDiffUtils.filterByType(<root>, <type>) identifies a method whose source differs between old and new as a modified METHOD node whose id contains the method name [k31]

StructuralDiffUtils.hasChanges:
In short: StructuralDiffUtils.hasChanges determines if a diff tree contains modifications. It returns true when the root or any descendant is added, deleted, or modified. It returns false when the root and all children are unchanged.

StructuralJavaDiffBuilder.diffJavaFile:
In short: StructuralJavaDiffBuilder.diffJavaFile compares two versions of a Java file. It returns a non-null root node with the file path as its id and FILE as its type. It classifies the root as added when old content is null, deleted when new content is null, modified when content differs, and unchanged when content is identical.
- StructuralJavaDiffBuilder.diffJavaFile(<relPath>, <oldContent>, <newContent>) returns a non-null root node whose id is <relPath> and whose type is FILE [k25]
- StructuralJavaDiffBuilder.diffJavaFile(<relPath>, <oldContent>, <newContent>) returns a root node that is unchanged and the tree has no changes when old and new content are identical [k26]
- StructuralJavaDiffBuilder.diffJavaFile(<relPath>, <oldContent>, <newContent>) returns a root node classified as added and the tree has changes when old content is null [k27]
- StructuralJavaDiffBuilder.diffJavaFile(<relPath>, <oldContent>, <newContent>) returns a root node classified as deleted and the tree has changes when new content is null [k28]
- StructuralJavaDiffBuilder.diffJavaFile(<relPath>, <oldContent>, <newContent>) classifies the root FILE node as modified when the file content differs [k32]
