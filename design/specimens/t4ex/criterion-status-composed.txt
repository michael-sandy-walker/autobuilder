What it is: A tool that reads an acceptance criterion about an HTTP endpoint and a specification stating response statuses for endpoints, extracting the asserted endpoint/status and the stated behaviours to compare them. [r2, r3, r4, r5]

Endpoint:
- Renders the endpoint as its verb, a single space, then its path via `Endpoint.toString()` [k1, k60]

- Collapses runs of duplicate slashes into a single slash via `EndpointPaths.normalizePath(String)` [k14]
- Lower-cases the path via `EndpointPaths.normalizePath(String)` [k15]
- Replaces every path variable with the empty braces placeholder via `EndpointPaths.normalizePath(String)` [k16]
- Drops a trailing slash from a multi-segment path via `EndpointPaths.normalizePath(String)` [k17]
- Returns null for null input via `EndpointPaths.normalizePath(String)` [k18]
- Returns null for blank input via `EndpointPaths.normalizePath(String)` [k19]
- Returns null when the path is only a query string with no path part via `EndpointPaths.normalizePath(String)` [k20]
- Returns null for the bare root path via `EndpointPaths.normalizePath(String)` [k21]
- Returns the trimmed query string that `normalizePath` discards via `EndpointPaths.discardedInput(String)` [k22]
- Returns empty when the path has no query string via `EndpointPaths.discardedInput(String)` [k23]
- Returns empty when the query string is empty or whitespace-only via `EndpointPaths.discardedInput(String)` [k24]
- Returns an empty set when the text is null via `EndpointPaths.declaredIn(String)` [k25]

SpecEndpointBehaviourQuery.StatedBehaviour:
- Renders the status alone when the condition is null or blank via `SpecEndpointBehaviourQuery.StatedBehaviour.toString()` [k47, k58]
- Renders "status condition" when a non-blank condition is present via `SpecEndpointBehaviourQuery.StatedBehaviour.toString()` [k47, k59]

BehaviouralCriterionParser:
- Parses a criterion naming exactly one verb-qualified endpoint and exactly one marker-introduced status in the 100-599 range to an assertion carrying that verb, the normalized path, and that status via `BehaviouralCriterionParser.parse(String)` [k61]
- Abstains (returns empty) when a criterion names two distinct endpoints via `BehaviouralCriterionParser.parse(String)` [k63]
- Abstains (returns empty) when a criterion states two distinct response statuses via `BehaviouralCriterionParser.parse(String)` [k64]
- Abstains (returns empty) when a criterion has no endpoint, or has an endpoint but no marker-introduced status via `BehaviouralCriterionParser.parse(String)` [k65]
- Returns empty for null and blank input via `BehaviouralCriterionParser.parse(String)` [k66]
- Normalizes a path variable to a single {} placeholder in the parsed path via `BehaviouralCriterionParser.parse(String)` [k67]
- Accepts "status" and "status code" as introducers of the expected status via `BehaviouralCriterionParser.parse(String)` [k68]
- Accepts a response verb ("returns") alone as a status marker via `BehaviouralCriterionParser.parse(String)` [k69]
- Does not read a bare three-digit number not introduced by a marker as a status, abstaining instead via `BehaviouralCriterionParser.parse(String)` [k70]
- Does not read a marker-introduced number outside the 100-599 range as a response status, abstaining instead via `BehaviouralCriterionParser.parse(String)` [k71]
- Parses a criterion whose stated input is a pattern (contains {}) to an assertion but returns empty from `exercisable` via `BehaviouralCriterionParser.parse(String)` and `BehaviouralCriterionParser.exercisable(String)` [k72]
- Recovers the query-parameter component a criterion names beyond the path it addresses, returning it verbatim via `BehaviouralCriterionParser.statedInput(String)` [k73]
- Returns the full query string when the criterion names several parameters via `BehaviouralCriterionParser.statedInput(String)` [k74]
- Returns empty when the criterion names no query-parameter input via `BehaviouralCriterionParser.statedInput(String)` [k75]
- Returns empty for a null criterion via `BehaviouralCriterionParser.statedInput(String)` [k76]
- Returns the name of the single query parameter the criterion states via `BehaviouralCriterionParser.statedParameterName(String)` [k77]
- Returns empty when the criterion names no query parameter via `BehaviouralCriterionParser.statedParameterName(String)` [k78]
- Returns true when the criterion states the named parameter is missing via `BehaviouralCriterionParser.statesAbsentInput(String, String)` [k79]
- Returns true when the criterion states the named parameter is absent via `BehaviouralCriterionParser.statesAbsentInput(String, String)` [k80]
- Returns true when the criterion states the named parameter is omitted via `BehaviouralCriterionParser.statesAbsentInput(String, String)` [k81]
- Returns true when the criterion states the named parameter is not provided via `BehaviouralCriterionParser.statesAbsentInput(String, String)` [k82]
- Returns true when the criterion states the named parameter is not supplied via `BehaviouralCriterionParser.statesAbsentInput(String, String)` [k83]
- Returns true when the criterion states the request is made without the named parameter via `BehaviouralCriterionParser.statesAbsentInput(String, String)` [k84]
- Returns true when the criterion contains a verb-qualified path mention (one of GET/POST/PUT/PATCH/DELETE followed by a path starting with "/") via `BehaviouralCriterionParser.mentionsSurface(String)` [k85]
- Returns true for a GET endpoint mention via `BehaviouralCriterionParser.mentionsSurface(String)` [k86]

- Returns false when the criterion contains a verb but no path starting with "/" via `BehaviouralCriterionParser.mentionsSurface(String)` [k93]

- Returns false for a criterion that mentions an HTTP verb in prose but not as a path qualifier via `BehaviouralCriterionParser.mentionsSurface(String)` [k96]

BehaviouralCriterionParser.Assertion:
- Carries the criterion text verbatim (stripped) and renders "verb path → status" via `BehaviouralCriterionParser.Assertion.describe()` [k62]

SpecEndpointBehaviourQuery:
- Returns an empty map when the specification is null, blank, or names no endpoint at all via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k37]
- Binds a status stated inside an endpoint's own clause to that endpoint, carrying the specification's own condition wording that follows the code via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k38]
- Does not treat a three-digit number that is not a valid HTTP response status as a stated status via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k39]
- Binds a cross-cutting status stated in a paragraph that names no endpoint to an endpoint only when that endpoint's own clause states an input constraint via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k40]
- Does not bind a cross-cutting status to an endpoint whose clause states no input constraint via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k41]
- Omits an endpoint whose clause states no status at all from the returned map via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k42]
- Does not allow an endpoint's clause to cross a paragraph boundary, so a trailing paragraph's codes do not leak into the last endpoint's clause via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k43]
- Does not duplicate a cross-cutting status already stated in an endpoint's own clause for that endpoint via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k44]
- Trims the condition wording following a stated code at the next clause break (semicolon, comma, period, closing paren, or newline) via `SpecEndpointBehaviourQuery.statedBehaviours(String)` [k48]
- Renders each behaviour as "<verb> <path> returns HTTP <status>" plus the condition wording when present via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k45]
- Returns an empty list when the endpoint or the behaviour list is null via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k46, k52, k53]
- Treats a blank condition the same as a null one, emitting no trailing dash or text via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k51]
- Returns an empty list for an empty behaviours list via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k54]
- Emits one criterion per behaviour, in the same order as the input list via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k55]
- Renders a criterion that is read back by the executable-criterion parser as the same verb, path and status via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k56]
- Renders a criterion with a condition that is still read back by the parser as the same verb, path and status via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k57]
- Renders each behaviour as a single string of the form "<verb> <path> returns HTTP <status>" when the behaviour carries no condition via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k49]
- Appends the behaviour's condition wording after the status, separated by an em-dash, when a non-blank condition is present via `SpecEndpointBehaviourQuery.criteriaFor(Endpoint, List<StatedBehaviour>)` [k50]
