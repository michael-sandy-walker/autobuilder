**Event (2026-06-16 T1-FA validation run, order-checkout seed, synthesize-members off):** root marked COMPLETED in 8 min / 13 cyc / 6 merges — the **first false completion in the corpus** (the zero-false-completions invariant had held across n=14). The artifact had all endpoint *shells* but was hollow: `OrderService.checkout` → `return null;`; `calculatePriceBreakdown` → `// Implementation would…` + `new PriceBreakdown()` (tax/total never computed); no `@ControllerAdvice` (business rules throw raw `RuntimeException` → HTTP 500, not the spec'd 400/404/409+JSON); `OrderRepository.saveOrder` never called (`GET /orders/{id}` always empty). The T4-BP coverage gate certified **"18/18 candidate gaps already implemented"** — a wholesale verifier false-positive (the local-model precision ceiling).

**The insight — the bug was load-bearing.** T1-FA ([[feedback-activity-not-progress]] applied at goal synthesis) correctly stopped grounding `[UNDEFINED]` markers leaking into persisted subgoal criteria. But those unsatisfiable marker-poisoned blockers had been *accidentally preventing* the root from closing — masking the verifier's tendency to green-light a shallow artifact. Remove the (wrong-reason) brake and the loop sails to a COMPLETED the verifier never should have approved. Net swing: **honest GIVEN_UP (wrong reason) → false COMPLETED (hollow)** = a regression on the metric the project cares most about. A correct fix can unmask a worse latent failure; always re-validate the *outcome*, never assume a mechanically-correct fix improved the run.

**Root systemic gap:** the completion edge (coverage → package → test) has **no deterministic BEHAVIORAL check**. Package gate = "compiles", test gate = "tests pass" (abstains with no tests). Stub bodies (`return null;`, comment-only) compile and pass both. So the *only* semantic guard is the LLM coverage verifier — and it false-positives. 

**Fix direction — chosen 2026-06-16: positive per-criterion corroboration (T4-BP step 3), NOT stub heuristics.** First attempt was a deterministic `StubBodyDetector` (`return null;`/empty bodies + a `PLACEHOLDER_MARKERS` list of comment phrases). The user rejected it: the marker list is the same frozen-string-scraping anti-pattern as T1-EZ/T2-EF ([[feedback-activity-not-progress]]) — English-only, gameable, a guess about how stubs *look*. Key realization from the pushback: I judged the artifact hollow by *reading* it (traced wiring against the requirement), not by markers or execution — and the system already HAS a read-and-compare verifier (the LLM coverage gate); it just reasoned shallowly (presence-matching) over a flat blob. So the lever is the LLM's **pattern recognition**, applied criterion-by-criterion against the current code, with the *inverse* framing of the coverage gate ("is this criterion satisfied?" not "is this gap implemented?"). `StubBodyDetector` reverted. Shipped: `CriteriaVerificationService.verifyCompletion` re-verifies the passing subgoals' acceptance criteria against current output at the completion edge; blocks COMPLETED + injects unconfirmed criteria. Digest-cached + call-counted ("too much LLM communication?" answered by practice, not guessed). **Caveat:** same local model that false-positived — focused per-criterion framing should raise precision but isn't proven; validate it CATCHES the hollow artifact, not just that it runs. Open design smell (user-flagged): the cache is an in-memory `verdictCache` — the codebase's pattern is graph-backed `CriterionResult` (already keyed by `criterionKey`); the verdicts should live there (digest-tagged), not a parallel ephemeral map. Local-first backstop for the verifier ceiling; execution rejected as non-general (complex projects can't always run). [[project-local-first-constraint]]
