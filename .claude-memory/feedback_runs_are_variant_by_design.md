Every autonomous run is variant — there is **no guarantee one run behaves like another, and that is as designed** (genuine runs go this way or that; the stochasticity is a feature, not noise to be normalized away). User steer, 2026-07-07.

**Why:** treating two runs as "the same failure" manufactures a story the data doesn't support — the naming-bias trap again ([[feedback-no-invented-labels]], [[feedback-neutral-vocabulary]], [[feedback-no-defensive-recast]]). It also over-couples fixes to a pattern that may not recur.

**How to apply:** when a run resembles an earlier one, say so ABSTRACTLY — "this rhymes with the text-vs-structure disagreement seen before" — not "same as run 18." A family resemblance at the mechanism level is fine and useful; asserting a repeat, a shared trap instance, or that run N "recurred" is not. The direction of a mechanism (e.g. a criteria checker reading MET vs UNMET) can flip run to run precisely because runs are variant. Diagnose the run in front of you on its own terms first; reach for the cross-run generalization only after, and keep it loose.
